## Implementation Summary

### Phase 2.1: Token Counter (`src/agent/token-counter.ts`)

**Purpose:** Estimate token usage for messages and tool definitions.

**Approach:**
- Character-based approximation (~4 chars per token)
- Simple but effective for MVP
- Can be upgraded to tiktoken in production

**Features:**
- `countText()`: Estimate tokens in plain text
- `countMessage()`: Count tokens in conversation messages with role overhead
- `countMessages()`: Sum tokens across message arrays
- `countToolDefinitions()`: Estimate tokens for tool schemas

**Test Coverage:**
- 22 tests written first (TDD RED → GREEN → REFACTOR)
- 100% statements, 100% branches, 100% functions, 100% lines
- Edge cases: null/undefined, empty inputs, unicode, special characters, large arrays

### Phase 2.2: Context Builder (`src/agent/context-builder.ts`)

**Purpose:** Construct completion requests and manage context within token limits.

**Features:**
- `buildRequest()`: Build completion requests with proper optional field handling
- `estimateTokens()`: Get token breakdown (messages, system, tools, total)
- `truncateHistory()`: Remove oldest messages while preserving tool call/result pairs

**Test Coverage:**
- 28 tests written first (TDD RED → GREEN → REFACTOR)
- 86.58% statements, 82.85% branches, 100% functions
- Edge cases: empty arrays, long content, tool call pairing, zero tokens

**Key Design Decisions:**
1. **Optional field handling**: Used object spread to conditionally include undefined fields in completion requests
2. **Tool call/result preservation**: Ensured tool calls and their results stay together during truncation
3. **Always keep last message**: Prevents empty context even when token limit is exceeded
4. **Type safety**: Proper type guards for message role checks and optional chaining

## Key Learnings

### TypeScript Strict Mode Challenges
- `exactOptionalPropertyTypes` requires explicit handling of optional fields
- Cannot assign `undefined` to optional readonly properties
- Solution: Object spread with conditional inclusion

### Tool Call/Result Pairing
- Complex edge case in history truncation
- Need to handle both forward and backward pairing
- Type guards essential for distinguishing message types

### Token Estimation Accuracy
- Character approximation sufficient for MVP
- Typical: 1 token ≈ 4 characters in English
- Production would use tiktoken or provider-specific counters

## Technical Decisions

### Why Character-Based Token Counting?
- Simple and fast for MVP
- No external dependencies
- Reasonable accuracy for English text
- Can be upgraded later without API changes

### Why Preserve Tool Call/Result Pairs?
- Tool results without context are meaningless
- Models need to see what they asked for
- Prevents broken conversation flow

### Why Conditional Object Spread?
- TypeScript `exactOptionalPropertyTypes` enforcement
- Cleaner than property assignment
- Maintains readonly immutability
- Standard pattern for optional fields
